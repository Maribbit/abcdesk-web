# 乐谱渲染 (Rendering Specs)

把纯文本 ABC 变成浏览器里的矢量乐谱，并在出错时给出可用的诊断。

## 1. 核心概念

- **解析与排版 (Parser & Engraver)**：由 `abcjs` 完成文本到 SVG 的转换，本项目只做封装，不自己解析 ABC。
- **质量诊断 (Diagnostics)**：收集底层词法/语法告警，转成带源码位置的诊断对象，供编辑器面板与后续修复提示使用。

## 2. 排版契约

### 2.1 响应式重排

预览区宽度由用户拖拽分栏决定，会频繁变化。

- 用 `ResizeObserver` 监听容器宽度。
- 变化超过阈值才重排，且必须复用现有解析结果、只换 `staffwidth`；禁止重新请求资源或从头重新解析。
- 重排抖动必须收敛：连续拖拽期间不重复触发完整渲染。

### 2.2 SVG 颜色覆写

abcjs 产出的 SVG 在内联属性里硬编码填充色。

- 只用 CSS（`currentColor` 及 CSS 变量）覆写，不改 DOM 属性，保证深浅色切换与主题一致性。
- 颜色规范由 `interface.md` 约束。乐谱容器必须是不透明表面，透明纸材质只用于外层 chrome。

### 2.3 一个共享目标

光标所在的音与点击的音是同一个状态，不是两套高亮。

- 映射只写一次：`pointSourceOffset` 把源码偏移映射到 timing event。光标移动与谱面点击都走这一条路，两侧永远指着同一个音。
- 后到的意图覆盖先到的（latest wins）：动光标、点音符，谁最新算谁。
- 源码侧按“光标站着的字符”判归属：光标画在它左边那个字符旁边，所以音符后的空白仍属于这个音（点 `C` 的右边缘不会跳到 `D`）；只有光标真正到达下一个音的首字符时才换目标。但小节线是例外：它结束的是刚读完的小节，所以光标贴在 `|` / `|]` / `:|` 之后指向的是下一小节的第一个音，而不是上一小节的最后一个。
- 谱面侧听 abcjs 的：它的命中半径是一个音符周围的矩形，不是符头本身，所以点音符旁边也会选中它；容器只在 abcjs 完全没认领时放手（点到乐谱之外）。两套判定只有一套——哪一边都不另外加自己的命中规则。
- 「这个点击认领了没有」不能存在某一次渲染的闭包里：改文本、重排都会给 abcjs 一个新的 `clickListener`，认领要写在所有监听共同的入口上，否则重排之后点音符会被当成「点在空白上」，把刚刚设上的目标又收走——看上去就是联动全丢，只剩进度条在动。
- `abcelem.startChar` / `endChar` 是位置真相，不要自己重新扫描文本去猜音符边界；它是按“一个音到下一个音”给的，区间两端带分隔空白，落到音符本身前必须裁掉。
- 标记是被动的：不 seek、不播、不夺焦。点击音符顺带 seek 是另一件事，与标记互不依赖。
- 键盘是第三块屏，说同一件事：目标音对应的琴键用同一族的亮蓝填上，与源码、谱面一起指同一个音。
- 标记与起播问的不是同一个问题：标记用 `findTimingEventAtCaret`（间隙归左边那个音），起播用 `findTimingEventForSourceOffset`（间隙归还没响的下一个音）。两者共用同一份 timing 与裁剪，只差间隙的归属，这是有意为之。
- abcjs 自己的点击选中色（`selectionColor`）在渲染时改成 `currentColor`，让原生选择不可见，页面上只保留一种“选中”语言。
- 光标停在 `X:` / `T:` / `K:` 等文件头里时没有目标，谱面回到顶部。

### 2.4 标记的画法

同一个目标在两处用同一种语法——虚线框——来画。

- 谱面：音符填充成亮蓝，外加一个虚线框。框画在 abcjs 自己的 SVG 里（`<g class="abcdesk-target-layer">` + `<rect>`），用 `getBoundingClientRect` 与 `viewBox` 反算回用户坐标，所以分栏缩放时框不会漂移；`vector-effect: non-scaling-stroke` 让线宽始终是 1.5px。
- 一个音符簇一个框：和弦是一簇，延音线展开出的每个音各自一簇。
- 源码：音符字符加淡蓝底 + 虚线 `outline`（不是 `border`：inline 边框会在标记出现时把字符横向挤开）。底色让标记在整行里先被看到，虚线说清楚是哪几个字符；两者都不能像文本选区，否则会和读者自己拉的选区混为一谈。同一段字符既指着又在响时，两层装饰是嵌套的两个 span，底色叠加（比纯播放色深一步），虚线框仍然说明它是目标；这一处不像谱面和键盘那样由播放色独占。
- 源码光标是折叠的：框已经承担了“就是这几个字符”的语义，再拉一个选区就是第三种说法。
- 播放高亮是另一套：实心蓝、不画框。形状把“正在响”与“我指着”分开，即使两者落在同一个音上。
- 这套颜色只发给真的在响的音：停止时点击谱面只移动播放位置，不染色。abcjs 的 seek 也会回调音符事件（`setProgress` 不区分播放状态），这类回调要按播放状态挡住，否则旧的点击会留下一个亮着的音，看上去就是第二套选中。
- 键盘上的目标不是这套蓝色，而是目标的亮蓝（`--abcdesk-target`，比播放蓝浅一阶、更冷）：同一个键既被指着、又真的在响时，后出现的播放规则赢，键上是播放蓝。
- 目标只在需要时重新指向：文本变了就清空、等下一次指向；布局重排（文本未变）原地重指。

### 2.5 源码到谱面

反方向不点、不播，只回答“我在这儿”。

- 光标移动时把目标音符所在的谱行滚进视野；不 seek、不高亮、不抢焦点，播放状态不受影响。
- 目标是整行谱表（`.abcjs-staff-wrapper`），不是单个音符：音符是一个点，读者需要的是它所在的那条线。
- 滚动只发生在音符真的出了视野时（`block: "nearest"`），并用 `scroll-padding` 留出呼吸位，避免谱表贴着边缘被切。
- 编辑时不在每次击键上跟随，而是等重渲染落地后再指一次，不去追一张已经过时的谱。

### 2.6 打印

`Cmd-P` 得到的应该是一张谱，而不是应用的截图。

- 纸只留读的人会钉到墙上的东西：曲名、曲名上方的记谱提示、谱表本身。顶栏、源码、拖拽条、对话框在页面层收起（`src/workspace/styles/print.css`），走带、键盘、质量面板在播放器层收起（`src/player/view/styles/print.css`）。
- 屏幕用 `absolute` 定位的 SVG 加 `padding-bottom` 百分比撑高谱面；纸上没有窗口，只需让 SVG 回到常规流、高度随宽，页就自己长。
- 打印宽度由纸决定，与视口无关：SVG 缩放填满纸宽，所以 700 与 1600 宽的窗口打出来是同一张谱。
- `renderAbc` 交给一个元素时只画第一首曲（它把单个元素当成只有一首），所以一张 SVG 就是一首曲；分页与多曲是两件事。
- 浏览器不认 SVG 内部的分页，长谱会在页边界被横向切开谱表。打印前把每个 `g.abcjs-staff-wrapper`（一行谱表）拷进自己的 SVG，`viewBox` 裁到本行所在的那一带，并 `break-inside: avoid`，页就只能在行与行之间断开。
- 断点落在相邻两行的中点：上下各留半格空白，断页不会啃掉上一行；两行重叠（第二个声部、拥挤的段落）时中点会退到上一道缝之前，必须夹紧向前，否则会出现高度为零的页。
- 不属于任何一行的装饰（`<style>`、`<title>`）要拷到每一页：前者是字形的画法，后者是这张图的姓名。
- 分页是临时状态：`beforeprint` 与 `matchMedia("print")` 两种信号都会触发，`afterprint` 还原成屏幕认得的那张 SVG（分页本身是幂等的，重复触发无害）。打印期间的布局宽度来自纸而不是窗格，重排必须让路，否则会把正在打印的分页结果重新渲染掉。
- 目标与播放高亮属于读者的会话，不是曲子属性：打印时用 `revert` 交还原墨，空心符头仍然空心。

## 3. 边界条件

- **XSS**：`T:`、`w:` 等字段来自用户手写或 AI 生成，进入 DOM 前必须清洗。
- **超长乐谱**：容器需有 `max-height` 与视口约束，不能无上限撑爆布局。
- **空输入**：清空时销毁实例、移除 SVG，状态回到就绪，而不是渲染空谱。

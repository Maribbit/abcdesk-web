# 独立工作台 (Workspace Specs)

Workspace 是产品本体：一个无后端、纯客户端的 ABC 草稿本与乐谱游乐场。

## 1. 定位

- 不依赖任何宿主或浏览器特权 API，可以部署为纯静态站点。
- 播放器是它的预览内核，两者保持单向解耦：Workspace 依赖 Player，Player 不知道 Workspace 存在。

## 2. 状态生命周期

无后端时，状态如何存活是首要设计问题。

### 2.1 URL hash 分享

- 源码写入 `#abc=` 作为跨设备分享与草稿恢复的链路；标题栏的 `Copy Share Link` 复制整条链接，起点取页面自己的 origin 与 pathname，子路径部署也不会指错地方。
- 压缩后再编码：`abc=z1.` + base64url(deflate-raw)，典型乐谱约为百分号编码文本的三分之一——链接得先短到能塞进一个聊天窗口。`z1.` 同时是版本标记：它区分压缩载荷与老链接里的 `encodeURIComponent` 文本，而 ABC 文件只能以字段行开头，百分号编码不可能让载荷以 `z1.` 起头，所以两种链接可以共存。
- 编解码依赖浏览器的 `CompressionStream` / `DecompressionStream`，所以这条契约是异步的；能力缺失时退回纯文本编码，链接变长但仍然可用。解不开的载荷（被截断或手改）按“没有 hash”处理，不抛错。
- 初始化时解析 hash 取得源码，随后用 `replaceState` 清掉 hash，避免刷新时覆盖用户后续编辑。

### 2.2 本地私有状态

- 换行开关、主题模式、分栏模式、关键词诊断开关与最近一次源码存在 `localStorage`。
- 这些是用户私有偏好，不随 hash 分享。
- 所有存储访问集中在 `settings-store.ts` 适配层，工作台不对存储方式做假设。

### 2.3 离线（PWA）

- 清单 `manifest.json` 与 `sw.js` 都随构建产出。清单用 `.json` 而不是规范推荐的 `.webmanifest`：静态托管（EdgeOne）按扩展名给 MIME，不认识的扩展名一律 `application/octet-stream`，清单就成了一个“二进制块”而不是应用说明。清单里的 URL 全部相对自身，子路径部署不需要另一份清单；图标由 `scripts/generate-icons.mjs` 从两份 SVG 出：16/48/128 用 `public/icons/icon.svg`（透明的标记本身），192/512 两个安装图标用 `scripts/icon-app.svg`（同一枚音符垫一张平纸）。",
- `sw.js` 不是源码里的静态文件：构建插件读 `src/pwa/service-worker.js` 模板，把本次产出（带内容哈希）的文件名与 88 个 samples 填进去。版本号是这份名单的哈希——只改动不被缓存的代码时，读者不必重新下载一遍应用壳。
- 安装时应用壳是“要么全有要么全无”：`cache.addAll` 失败就让安装失败，半套缓存离线打开只会得到一个脚本永远不来的页面。样本则尽力而为，单个失败不阻塞安装，首次用到时再取。
- 样本缓存不带版本号：88 个永不变化的 mp3 不该在每次发布后重下，所以它跨构建存活，只补缺的。
- 页面导航网络优先、离线回落到缓存里的壳，于是新版本在下一次刷新就生效而不是等缓存过期；其余请求（bundle、样本、图标）都是内容寻址或不可变的，缓存优先，只在缺失时才访问网络。
- 查缓存时忽略 `Vary: Origin`：安装是 worker 自己去取文件，请求不带 `Origin`；而服务器（Vite 的预览服务器就是如此）给带 `crossorigin` 的脚本与样式回 `Vary: Origin`。不忽略的话，离线时恰好缺的就是这两个开不了机的文件。缓存归本应用所有、每个 URL 只存一份表示，所以忽略而不是伪造这个头。
- 激活时删掉上一版的壳缓存，样本缓存不受影响。
- 新 worker 装好后停在 waiting：激活就会删掉旧壳，而打开的页面还在跑旧代码，替它做这个决定会让页面去要已经不存在的文件。页面在标题栏里放一枚 `New version ready` + `Reload` 的小签，读者按下才发 `skip-waiting`，等 `controllerchange` 后刷新。首次安装没有可替换的 worker，它直接激活并接管当前页，不弹提示——“更新”按“有东西可替换”判定，而不是按“有个 worker 装好了”。
- 只在生产构建注册，作用域就是部署基路径（`SITE_BASE`），不会替同源下的其他应用作答；浏览器拒绝时（隐私模式、策略）只失去离线副本，在线功能不变，控制台留一条警告。离线副本是增强，不是前提。
- 断网时标题栏出现一枚 `Offline` 小签，和 `New version ready` 共用标题栏中间的那一个位置（状态填在同一个槽里，不各占一边）。它是纸的一部分而不是警报：只有描边、用页眉自己的小字与字距，不浮起、不上红——离线是这个应用的常态，谱面照常可读可编辑。标签跟 `navigator.onLine` 与 `online` / `offline` 事件走，不轮询；悬停提示只在真的有 worker 接管时才承诺“从保存的副本运行”，否则只说“没有网络”，不替没能生效的副本背书。

### 2.4 页面身份（标签与链接卡片）

- 标签页跟随曲名：渲染成功后用 `T:` 写 `document.title`（`曲名 — ABC Desk Web`）；空谱、解析失败或没有 `T:` 时回到应用名。标题取渲染出来的那份 `visualObj`，不取还在防抖里的输入——标签说的是纸上的东西。
- 首屏 `head` 自带 `description`、OG/Twitter 卡片与 `public/social-card.png`（1200×630，工作台实拍，用同一套纸与同一份示例，不画假界面）。曲子写在哈希里、爬虫读不到，所以卡片只承诺工作台，把乐谱留给打开的人。
- 严格客户端要绝对地址：`SITE_URL` 默认就是 `https://abcdesk.maribbit.com/`——站点地址是项目的事实，不是构建机器的事实；构建时把卡片与 `canonical` / `og:url` 补成完整 URL，预发或换域名时用环境变量覆盖。
- `theme-color` 跟随解析后的主题（手动或系统），值直接读 `--workspace-bg`——CSS 仍是颜色的唯一出处。地址栏与墙同色，而不是另给一个意见。
- 无脚本时隐藏跑不起来的界面，墙上留一句说明：它比一套空壳控件诚实。
- **标记是一枚棱面音符**：顶栏那枚不是带渐变与圆角的徽章，而是一枚用多边形画出来的八分音符——菱形音符头、方条符干（末端斜切进音符头的右尖）、带缺口的平行四边形符尾，单一颜色、全是硬角、下面什么都不垫。画风与作者博客的家具同一套（六边形钟面、平涂色块）：这一枚是全站唯一的主体图形，因此不比 UI 里的描边图标圆、不比它亮，也不给自己加第二层。它写在 `index.html` 里（`<img>` 继承不到主题色）、用 `currentColor` 取 `--workspace-accent`；标签页的 `public/icons/icon.svg`、安装图标的 `scripts/icon-app.svg` 与它是同一份多边形，`brand-mark.test.ts` 逐点比对三处，改一处不改另一处会红。标签页那枚跟着系统主题换墨色（浅色 `#4f6779`、深色 `#9ab0c2`）——标签栏是唯一会问 `prefers-color-scheme` 的地方，单一的中间灰在两边各丢一半。安装图标是唯一给它垫纸的场合：主屏上没有桌面可读，透明字形会糊成一团，所以 192/512 是同一枚音符平铺在 `#eef2f3` 上，仍是硬角，圆角交给系统去切。
- **字与标记并排的那一行是 `ABCDESK`**：一个词、不带空格，是小写字距加宽的字标——它不是应用名，只是这枚音符的字号注脚。应用名仍是 `ABC Desk Web`：标签页标题、About 的标题、`og:` 卡片与包装清单里都写全三个词，读者搜索和收藏的是那个名字。

## 3. 交互链路

- **左屏：源码编辑器**：工作台只通过 `AbcEditor` 门面（取值、写入、播放高亮、目标轮廓、诊断与跳转、换行、光标位置）使用编辑器，不碰具体 DOM；当前实现是 CodeMirror 6，语法三档灰、诊断波浪线与目标底色、虚线轮廓都由装饰层绘制。左侧页边有行号，只做参照、不响应点击：行号比正文的任何灰都淡一档（浅主题 3.1:1、深主题 3.7:1），且与正文同一条基线——12px 的数字若按自己的行高坐在 13.5px 的行里，会整体上浮一两像素，所以行号是按基线对齐到一根零宽、码字号的行架（strut）上，而不是靠行高凑；光标所在行的行号回到正文色、整行铺一层中性灰——不是蓝色，因为目标音与播放音已经各占一支蓝，第三种蓝会让“我在这”读成“选中了”。有诊断的行在行号旁点一颗灰蓝圆点（与波浪线同色相、更实），于是面板里的 `Line 7` 在纸面上有一个可指的位置；同一行多条诊断只点一颗，它是指路，不是计数。诊断是上一版文本的报告：打字时它不消失——波浪线与圆点跟着文本走，面板也不收起来，否则编辑器每敲一键都要长高再缩回；状态行改说 `Editing...`，等 350ms 后的复查落地再整体换掉（多数时候换回来的还是同一份）。空源码没有复查可言，最后一份报告由渲染一并撤下。语法灰是增量维护的：一次编辑让未改动处的标记跟着文本走，只有被改到的行重新扫描，于是千行长谱的每键代价与文件长度基本无关。`Mod-/` 切换 `%` 注释：选区碰到的每一行各插一个标记，整块已经是注释时则原样收回；`%` 在 ABC 里从行首或行中一直吃到行尾，没有闭合的伙伴也没有嵌套，所以它就只是一行一次插入、一次删除——块内的空行不参与，否则开合一轮会留下需要手动清理的裸 `%`。
- **左屏：源码动作**：导入 `.abc` / `.txt`、导出当前源码、复制、复制分享链接、加载示例、清空，以及字符统计；源码为空时复制、导出与分享一并禁用。把文件拖到源码栏上就是另一种导入——一次手势代替三次点击：悬停时边框铺一层虚线提示可以放下，文字本身不动；页面其他地方的拖放一律拒绝，否则浏览器会把整页导航到那个文件、带走未保存的草稿。空源码时编辑器留一行提示语，说的正是这件事。
- **右屏：预览代理**：输入后按 350ms 防抖重新渲染，并刷新诊断面板与状态文案。
- **一个共享目标**：光标所在的音与点击的音是同一个状态。谱面用「音符染色 + 虚线框」显示它，源码给音符字符加淡蓝底色与虚线轮廓，键盘把对应的琴键填成同一族亮蓝；三处永远指的是同一个音，最新的意图（动光标或点音符）覆盖旧的。选择用亮蓝、播放用更深的蓝：两者同屏时靠颜色深浅与有无虚线框区分。
- **谱面到源码**：点击谱面上的音符（含它周围的命中区，与 abcjs 自己的选择半径一致），这个音成为共享目标，源码光标落到它对应的字符上（折叠光标、不抢焦点），同一位置的播放指针也跟着走——但只在播放中染色：停着的曲子只移动播放位置，不给任何音上色，否则旧的点击会留下来，看上去像第二套选中。点到乐谱之外的空白则两侧一起放手。
- **光标到谱面**：在源码里移动光标（方向键、点击、选区），同一个音成为共享目标——光标贴在音符右侧空白时仍属于该音——预览把对应的谱行滚进视野，键盘也把它的键填上；不播放、不高亮，光标停在文件头时三处都清空并回到谱面顶部。
- **从光标播放**：预览区播放条里、播放键左边的“从光标播放”键（左三角右光标，与播放键同高，用共享目标的蓝）与 `Mod-Enter` 是同一个意图，都从光标所在的音开始播放；编辑器只报告“用户想从这里听”，并不认识播放。这个键在播放条里，不在源码标题栏：它开的是声音，与播放键相邻而不是与文件操作相邻。它挂在共享目标上，没有目标音时是灰的禁用态——没有“这里”就没有“从这里播放”；快捷键不受此限，光标停在文件头时落到第一个音。
- **快捷键的归属**：光标属于工作台而不属于编辑器，所以 `Mod-Enter` 是页面级的——焦点在谱面、播放条、琴键上时它照样起播（`play-shortcut.ts` 在 `document` 上听 keydown），编辑器自己保留一份绑定，好让带修饰键的回车不插行；已经处理过的键靠 `defaultPrevented` 认出来，否则在编辑器里一按会起播两次。不响应的四种情形：打开着的 对话框（说明页背后不放音乐）、输入法还在组合、焦点在输入框/可编辑区（注意传输控 件住在 shadow root 里，`event.target` 会被重定向到宿主，所以看的是 `composedPath()` 的第一项）、以及带 Shift / Alt 的变体。`Mod-/`、`Mod-Z`、`Shift-Mod-Z` 作用 在选区与文档上，留在编辑器里。
- **空格是播放条自己的键**：起播、暂停、从停下的地方接着走，都是同一个空格（同一份 `play-shortcut.ts`，`isToggleShortcut`）。它不能在全页生效——源码里一个空格就是一个音符——所以源码与那些自己要用空格的控件（按钮、链接、`summary`、`role=button` 一类、输入框）都留着它，其余地方按空格就是按播放键；带修饰键的空格留给浏览器与系统。按下时不是另写一套播放状态，而是替读者点一下播放键：加载转圈、放到末尾后从头再来、暂停时收起高亮，这些都归 abcjs 的开关管，抄一份只会慢慢走偏。谱面为空时在状态行说 `Nothing to play here`，与从光标播放同一句话。
- **About 是一张短说明页**：顶栏右侧的问号打开它。“这是什么”用一句话回答，紧接着是五条组合键，分成四档，每档先回答“在哪儿算”：`Anywhere` 是 `Mod-Enter`（它跟光标走，与焦点无关），`Outside the source` 是空格（源码里它得先当音符，按钮也各自要用它），`In the source` 是 `Mod-/`、`Mod-Z`、`Shift-Mod-Z`（作用于选区与文档），`In the browser` 是 `Mod-P`——打印是浏览器自己的组合键，工作台能做的是给它一张纸（打印样式把分栏、顶栏与源码收起），所以它单列一档，不冒充页面级的绑定。把这层区别写进表格，比在文档里解释“为什么有时不灵”诚实。两段长说明（一次一首、MusicXML 转换）默认收起，用原生 `<details>` 承载：标题行本身就是开关，闭着时旁边的一行提示已经作答，展开后提示让位、箭头转下，键盘与读屏不需要额外实现。修饰键在标记里写死 `Ctrl`（无脚本或非 Apple 的机器读到的是真话），启动时按 `navigator.userAgentData.platform` → `platform` → `userAgent` 判平台，Apple 的机器整列换成 `⌘`（`shortcut-labels.ts`）：标记只写一次，脚本启动时也只改一次。拖入文件、分享链接与“可安装、离线可用”两句话收在脚注，作者与 GitHub 在页脚。手机上转换链接与 GitHub 链接各占一根手指的高度，但多出来的 padding 从 margin 里还回去，版面与桌面一致。
- **分栏**：可拖拽、可键盘调整，尺寸与方向持久化；窄屏自动降级为上下堆叠。

## 4. 约束

- 空源码不进入渲染流程，直接回到就绪态。
- 渲染失败必须显式反馈，不能只留空白预览。
- **一次一首**：`renderAbc` 交给单个元素时只排第一首曲，所以谱面、播放、高亮与键盘都只认第一首，而诊断扫整篇。这是现状而不是目标，About 必须写明，别让读者以为换到第二首会跟着走。
- 移动端不保留横向双栏，避免拖拽与滚动冲突。
- **手机（`@media (max-width: 600px)`）只保证第一分钟**：`360` / `390` 两个视口下页面不得横向溢出，顶栏与面板头部都是单行。顶栏收起 wordmark（图标本身就是签名），触区 44px；`Offline` 签与更新提示同时为真时只留后者——提示要人动手，`Offline` 只是报告；更新提示在手机上只画 `Reload` 按钮，句子留在 `role="status"` 里给读屏。面板头部 56px 高（与播放器 shadow 头部同高，由 `layout.css` 定），源码头收起复制与清空（分享链接已携带源码，清空在手机上无撤销），预览头收起浏览器全屏（系统全屏足够）；其余工具保留，编辑仍然是次要场景。键盘横向滚动用 `overscroll-behavior-x: contain` 约束在本组件内，拖到尽头不带动整页（不用 `touch-action: pan-x`：那会把从琴键上开始的竖向拖拽也一并禁掉）。

## 代码与测试映射

- **源码锚点**
  - `src/workspace/`: 工作台入口、分栏、源码动作、展示状态、诊断面板与渲染控制。
  - `src/workspace/styles/print.css`: 打印时的页面层（纸取代分栏，顶栏与源码收起）。
  - `src/workspace/styles/responsive.css`: 窄屏堆叠与手机单行顶栏、44px 触区、面板头部收起的工具。
  - `src/workspace/editor/`: 编辑器门面 `AbcEditor`、CodeMirror 6 实现（装饰层、换行与跳转）与纯净的语法扫描器。
  - `src/shared/workspace-url.ts`: hash 编解码，压缩载荷与老链接兼容。
  - `src/pwa/`: service worker 模板（不经打包）、构建期填充与生产环境注册。

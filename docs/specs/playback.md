# 播放引擎 (Playback Specs)

定义 ABC 如何变成声音，以及音频生命周期与时序对齐的规则。

## 1. 核心概念

- **Soundfont 调度**：本地 `.mp3` 采样按需异步加载，绝不请求远端音源。
- **合成器状态机**：基于 Promise 的受控对象，管理 `ready` / `playing` / `paused` / `disposed`。
- **时序与节拍**：以 abcjs 生成的事件流为准，用户设置的速度覆盖谱面 `Q:`。

## 2. 状态同步

### 2.1 游标

- 不用 `setInterval` 轮询音频时钟，依赖解码引擎的事件回调。
- 每次音符触发下发 `startChar` / `endChar`，据此同时更新乐谱元素与源码编辑器的高亮。
- 暂停不是时序事件，暂停时必须主动清掉残留在乐谱与源码上的高亮，否则高亮会一直停在最后一个音符上。
- 拖拽进度或点击音符跳转时，跳转本身可能落在事件边界上而被跳过，播放中必须在 seek 后直接补发一次高亮。
- 「正在响」的颜色只属于真的在响的音：停止 / 暂停状态下 seek 只移动播放位置，不给任何音符、琴键或源码字符上色。abcjs 的 seek 也会回调音符事件（`setProgress` 不区分播放状态），这类回调必须按播放状态挡住，否则旧音符会一直亮着，读者把目标移到别处后页面上就出现两套选中。

### 2.2 速度覆盖

用户手动设置的 BPM 优先；取消或重置时回落到 `Q:` 标定的原始速度。

### 2.3 从光标起播

源码位置到声音之间只有一段桥：timing event 同时带着字符区间与毫秒。入口有两个——播放条上「从光标播放」的键与编辑器里的 `Mod-Enter`——两者都只是把同一个位置交给同一段桥。

- 光标落在音符上就是那个音；落在两个音符之间，属于"还没响的那个音"——这才是"从这里开始"的意思。
- 光标越过最后一个音时，回落到最后一个音，而不是停在原地。
- 已经在播放时只改变位置，不再调用 `play()`；它会切换播放与暂停，会静音自己。
- 起播前先把还在防抖窗口里的编辑落地：否则光标会被映射到一张已经过时的谱上，随后到来的重渲染还会把刚起的播放暂停掉。
- 合成器可能还没就绪（首次加载音源，或刚被重渲染换掉），起播请求要排在它后面等就绪，而不是对着一个即将被替换的控制器下手。
- `play()` 要等音频上下文恢复才翻开关状态，所以同一时刻只允许一个起播请求；按住快捷键产生的重复键被丢弃。
- 播放条上的键读的是共享目标，不是“此刻的光标”：没有目标音时它是禁用态（没有“这里”就没有“从这里播放”），快捷键不读目标，所以不存在这个前提；光标在文件头时两者都落到第一个音。
- 起播键自己也防重：按下后先把自己禁用，等请求落地再按目标重新同步，否则第二次按下会落在正在切换的 `play()` 上，把刚起的播放又关掉。

### 2.4 键盘

键盘回答两个问题：这首曲子里有哪些音，此刻指着哪个音。

- 音高集合来自 timing event 的 `midiPitches`，而它只在 abcjs 展平曲子后才存在。展平是音源加载时做的那一步，但它本身不需要音频：第一次读 timing 前先跑 `setUpAudio`，键盘从第一屏起就认识谱子，不必等到首次播放。
- 目标音在键盘上用亮蓝填充（`--abcdesk-target`，比播放蓝浅一阶、更冷），与“正在响”的播放蓝分开；同一个键既被指着又真的在响时，播放色赢。
- 指向不清空、不滚动琴键：读者指的是音，不是“键盘现在该看哪里”。
- 琴键被点击是试听（`audition`），与共享目标无关，不要为此改写目标。

### 2.5 播放条

播放条在乐谱上方，不在键盘下方：读者点音符、跟谱行时视线在纸上，播放指针不该藏在一块可能已经横向滚动的键盘后面。

- 回到开头只有一种办法：把进度条拖到最左端。abcjs 自带的 `|◀` 重播键关掉（`displayRestart: false`），两个入口只会换来一次误点。
- 图标语言跟面板标题栏同一套：24 单位画在 15px 上、2px 圆头描边、`currentColor` 着色；播放三角与「从光标播放」里的三角是同一笔，暂停是两根圆头条，加载是一段圆弧（旋转由 abcjs 的 `abcjs-loading` 类负责）。
- abcjs 用类名决定显示哪个图标（`abcjs-play-svg` / `abcjs-pause-svg` / `abcjs-loading-svg`，状态挂在按钮上），所以只换图形、保留类名。`load()` 是唯一会重写这段标记的地方，换图标就在 `load()` 之后立刻做一次。
- 两个按钮用同一套居中规则（`display: flex` + `align-items: center`，图标 `display: block`）：abcjs 的按钮是块级容器，行内 svg 会贴着文字基线落下去，图标就会比隔壁的播放键高一截、看起来也更大。三角本身也按播放键的高度画（13.5 单位），两个键并排，谁也不该比谁重。
- 播放键左边是「从光标播放」：图形是左三角右光标（两半并排，表达“从这个位置开始”而不是“加一个光标角标”）。颜色用共享目标的蓝，但浅色主题下压深一档（`--abcdesk-target-deep: #0a7fd4`）：同一支蓝在纸上是染色，在播放条的灰底上做控件只有 2.7:1，压深后 3.8:1，才够得上控件所需的 3:1；深色主题的条底本身就暗，保持 `#1c9bff` 不变。它是播放条上唯一一个关于目标而不是关于曲子的动作，没有目标时变成灰的禁用态。它排在主播放键之前：具体动作在前，普通播放在后。

## 3. 约束

- 声音层不查询 DOM，状态完全由数据驱动。
- 同一时刻只允许一份乐谱发声：收到新的播放信号，其他实例立即自行暂停。
- 实例销毁必须停止并释放音频节点，不能留下幽灵音。

## 代码与测试映射

- **源码锚点**
  - `src/player/playback/`: 时序、速度、音色库、合成器、进度与高亮同步。
  - `src/player/playback/cursor.ts`: 源码偏移到 timing event 的桥接（从光标起播）。
  - `src/player/components/tempo-control.ts`: 速度 UI 与 abcjs tempo 输入的桥接。
  - `src/player/playback/transport-icons.ts`: 播放条图标的替换（保留 abcjs 的类名与状态切换）。
  - `src/player/playback/transport.ts`: 播放条的收尾——图标、从光标播放键、与共享目标同步的可用态。
  - `src/player/playback/play-from-cursor.ts`: 源码偏移到起播的入口（播放条的键与快捷键共用）。
  - `src/player/renderer.ts`: 播放生命周期、进度拖拽、点击跳转与实例释放。
- **测试锚点**
  - `src/player/playback/duration.test.ts`: 总时长读取、事件回退、倍率与展示格式。
  - `src/player/playback/tempo.test.ts`: BPM 读取、倍率换算、按小节推导与无效值展示。
  - `src/player/playback/cursor.test.ts`: 光标命中音符、音符间隙归属与越界回落。
  - `src/player/playback/timing.test.ts`: 读取 timing 前先展平曲子（音高从第一屏起可得）、展平失败不阻断时序。
  - `src/player/playback/transport-icons.test.ts`: 播放条图标换成面板同一套描边图形，保留 abcjs 控制显隐的类名。
  - `src/player/playback/transport.test.ts`: 从光标播放键的位置、禁用态、点击起点与不重复插入。
  - `src/player/playback/soundfont.test.ts`: 内置钢琴音源路径与音符重写策略。
  - `src/player/components/tempo-control.test.ts`: 速度组件与 abcjs tempo 输入同步。
  - `src/player/renderer.test.ts`: 实例清理、进度起播、播放事件到源码高亮的集成。
